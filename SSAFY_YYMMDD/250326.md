# Model

### Model class

※ 이제는 views 함수가 models와 소통할 것이다.

SQL언어로 가져온 데이터베이스를 파이썬 언어로 바꿔서 다뤄야 할 것이다. 

- Django Model
    - DB의 테이블을 정의하고 데이터를 조작할 수 있는 기능들을 제공
        
        ⇒ 테이블 구조를 설계하는 ‘청사진’
        
    
    ```python
    # 게시글이 저장될 테이블 설계 클래스
    class Article(models.Model): # Model이라는 부모 클래스가 이미 작성되어 있고 상속 받는다
    	# **필드**(열) 이름 = models.데이터의 유형(제약조건)
    	title = models.CharField(max_length=10) # 제목
    	content = models.TextField() # 내용
    ```
    
                                         ⬇️
    
    | id | title | content |
    | --- | --- | --- |
    | 1 | 제목1 | 내용1 |
    | 2 | .. | .. |
    | .. | .. | .. |
    - 작성한 모델 클래스는 최종적으로 DB에 다음과 같은 테이블 구조를 만듦

### Model Field

- DB테이블의 **필드(열)**을 정의하며, 해당 필드에 저장되는 **데이터 타입(Field types)**과 **제약조건(Field options)**을 정의
- Field Types
    - 데이터베이스에 저장될 ‘데이터의 종류’를 정의 (models 모듈의 클래스로 정의되어 있음)
    - CharField()
        - 제한된 길이의 문자열을 저장 (필드의 최대 길이를 결정하는 max_length 필수)
    - TextField()
        - 길이 제한이 없는 대용량 텍스트를 저장 (무한대는 아니며 사용하는 시스템에 따라 달라짐)
        
        ※ max_length를 쓸 수는 있는데, 실제로 검사하지는 않음… (쓰고 싶으면 CharField 써야함)
        
- Field Options
    - 필드의 **동작**과 **제약 조건**을 정의
    - 제약 조건 : 특정 규칙을 강제하기 위해 테이블의 열이나 행에 적용되는 규칙이나 제한사항

### Migrations

<aside>
💡

Migration 과정

1. model cass 변경
2. makemigrations
3. migrate
</aside>

- model 클래스의 변경사항 (필드 생성, 수정, 삭제 등)을 DB에 최종 반영하는 방법
    1. model class = 설계도 초안
    
    → 2. migration 파일 = 최종 설계도
    
    → 3. db.sqlite3 = DB
    
- migrations 핵심 명령어
    
    ```python
    # 2. model class 기반으로 최종 설계도 작성
    python manage.py makemigrations
    # 3. 최종 설계도를 DB에 전달하여 반영
    python manage.py migration
    ```
    
- 생성된 테이블명 규칙
    - 앱이름_클래스이름 = 테이블 이름

### 추가 Migrations

- DateTimeField 옵션 (optional, 선택적)
    - auto ⇒ 자동으로 저장

```python
# 게시글이 저장될 테이블 설계 클래스
class Article(models.Model): # Model이라는 부모 클래스가 이미 작성되어 있고 상속 받는다
	# **필드**(열) 이름 = models.데이터의 유형(제약조건)
	title = models.CharField(max_length=10) # 제목
	content = models.TextField() # 내용
	**created_at = models.DateTimeField(auto_now_add=True) # auto_now_add 데이터가 첨 생성
	updated_at = models.DateTimeField(auto_now=True) # auto_now 데이터가 저장될 때마다**
```

- 최종 설계도 업데이트하기
    - python [manage.py](http://manage.py) makemigrations
        
        ⇒ **선택 1) 대화를 유지하면서 직접 기본 값 입력 (db에 빈공간이 생기기 때문에)**
        
        - 알아서 장고에서 기본 값 설정해줌
        
        선택 2) 대화 나간 후 models.py에 기본 값 관련 설정
        
        if) 2번을 선택하게 되면, **기본값**을 ****인자에 넣어 줘야 함
        
        ```python
        	created_at = models.DateTimeField(auto_now_add=True**, default=기본값**)
        	updated_at = models.DateTimeField(auto_now=True)
        ```
        
    - git commit 처럼 migration 설계도를 쌓아서 복구/되돌리기 지원
- 추가된 필드는 새로운 설계로도로 만들어 지고, 원래 필드에 의존되는 형태이다.
    - 001_initial
    - 002_추가된 필드

### Admin site

- Automatic admin interface
    - Django가 추가 설치 및 설정 없이 자동으로 제공하는 관리자 인터페이스
        
        ⇒ 데이터 확인 및 테스트 등을 진행하는데 매우 유용
        
1. admin 계정 생성
    - python [manage.py](http://manage.py) createsuperuser
        - email은 선택사항이기 대문에 입력하지 않아도 됨
        - 비밀번호 입력 시 보안 상 터미널에 출력되지 않음
2. DB에서 생성 계정 확인 가능
    - 테이블 명 : auth_user
3. admin.py에서 모델 클래스 등록
    - 등록 안하면 admin site에서 못

### 데이터베이스 초기화

1. migration 파일 삭제
2. db.sqlite3 파일 사게

※ 아래 파일과 폴더는 지우면 안됨

__init__.py, migrations

- Migrations 기타 명령어
    1. python [manage.py](http://manage.py) showmigrations
        - migration (설계도) 파일이 migrate 됐는지 확인
        - [x] ⇒ migrate 됨
    2. python [manage.py](http://manage.py) sqlmigrate articles 0001
        - 해당 migrations 파일이 SQL 언어로 어떻게 번역되어 DB에 전달되는지 확인
