### DTL (Dajngo Template Languate)

- Template에서 조건, 반복, 변수 등의 프로그래밍적 기능을 제공하는 시스템
- DTL Syntax (외우지 말고 찾아서 쓰기)
    1. Variable
        - render 함수의 세번째 인자시다.
        - 딕셔너리의 key ⇒ templat에서 사용 가능한 변수명이 된다.
        - dot(’.’)를 사용하여 변수 속성에 접근할 수 있다.
    2. Filters
        - 표시할 변수를 수정할 때 사용한다.
            - 사용법 : 변수 | 필터
        - chained(연결)이 가능하며 일부 필터는 이자를 받기도 한다.
        - 60개 가량의 template filters가 있다.
    3. Tags
        - **반복** 또는 **논리**를 수행하여 **제어 흐름**을 만듦
        - 일부 태그는 시작과 종료 태그가 필요
        - 24개 가량의 template tag 제공
    4. Comments
        - DTL에서의 주석
    
    ### 템플릿 상속
    
    - **페이지의 공통요소를 포함**하고,
        - **하위 템플릿이 재정의 할 수 있는 공간**을 정의하는
        - 기본 ‘skeleton’템플릿을 작성하여 상속 구조를 구축
    - 상속 구조 만들기
        - skeleton 역할을 하는 사위 템플릿에 block 작성
        
        ```
        <!DOCTYPE html>
        <html lang="en">
        <head>
            <meta charset="UTF-8">
            <meta name="viewport" content="width=device-width, initial-scale=1.0">
            <title>Document</title>
        </head>
        <body>
            {% block content %}
            {% endblock content %}
        
        </body>
        </html>
        ```
        
        - 기존 하위  템플릿 (스켈레톤 코드 삭제 후 block으로 감싸기)
            - block으로 감싸진 코드가 상위 템플릿의 블록 안으로 들어가는 개념
        
        ```
        {% extends "articles/base.html" %}
        
        {% block content %}
        <p>{{digimon}}몬의 파트너는 {{partner}}입니다.</p>
        <h2>디지몬 목록</h2>
        <ul>
            {%for digi in partner_digimons%}
            <li>{{digi}}</li>
            {%endfor%}
        </ul>
        
        {%if digimon == '아구' or digimon == '파피'%}
            <p>주인공이군요</p>
        {%else%}
            <p>{{digimon}}는 궁극체도 없고 파트너도 {{partner}}입니다..</p>    
        {%endif%}
        {% endblock content %}
        ```
        
- 상속 관련 태그
    - ‘extends’ tag
        
        : 자식(하위)템플릿이 부모 템플릿을 확장한다는 것을 알림
        
        ※ 반드시 자식 템플릿 최상단에 작성되어야 함 (2개 이상 사용 불가)
        
    - ‘block’ tag
        
        : 하위 템플릿에서 재정의 할 수 있는 블록을 정의
        
        (상위 템플릿에 작성하며 하위 템플릿이 작성할 수 있는 공간을 지정
        

### 요청과 응답

- HTML form
    - 데이터를 보내고 가져오기
        
        : HTML ‘form’ element를 통해 사용자와 애플리케이션 간의 상호작용 이해하기
        
- ‘form’ element
    - 사용자로부터 할당된 데이터를 서버로 전송
        
        ⇒ 웹에서 사용자 정보를 입력하는 여러 방식(text, password, checkbox 등)을 제공
        
- fake Naver 실습
- action&method
    - 데이터를 어디(action)로 어떤 방식(method)으로 요청할지
    - action
        - 목적지 (전송될 URL)
        - 지정 안할 시 현재 form에 있는 페이지의 URL로
    - method
        - 어떤 방식으로 보낼 것인지
        - GET(전송 데이터가 URL에 담김), POST
- input element
    - 사용자의 데이터를 입력 받을 수 있는 요소
    
    ※ 핵심 속성 - name
    
    - name 속성
        - 사용자가 입력한 데이터에 붙이는 이름(key)
        - name속성에 설정된 값을 통해서만 사용자가 입력한 데이터에 접근할 수 있음
- Query String Parameters
    - &로 연결된 key=value 쌍, 기본 URL과는 물음표(?)로 구문

### HTML form

```python
# GET은 url로 입력되고, method 입력 안하면 action의 링크로 간다.
    <form action="/catch/" method="GET">
        <input type="text" name="message"> # name은 query의 key 값이다.
        <input type="submit">
    </form>
```

```python
# query로 들어온 key와 입력값을 이용하는 방법
# .GET 메소드를 쓰면 QueriDict 형식으로 와서, dictionary처럼 코딩 가능
def catch(request):
    print(request)                      # <WSGIRequest: GET '/catch/?message=%E3%85%87%E3%85%87'>
    print(type(request))                # <class 'django.core.handlers.wsgi.WSGIRequest'>
    print(request.GET)                  # <QueryDict: {'message': ['ㅇㅇ']}>
    print(request.GET.get('message'))   # ㅇㅇ
    context = {}
    context['message'] = request.GET.get('message')
    return render(request, 'articles/catch.html', context)
```

### Django URLs

- URL dispatcher (운항 관리자, 분배기)
    - URL 패턴을 정의하고 해당 패턴이 일치하는 요청을 처리할 view 함수를 연결 (매핑)
- 문제점 : URL은 많으 부분이 중복되고, 계속해서 비슷한 url 템플릿이 생긴다.
    
    ![image.png](attachment:d17345de-bc2b-4543-9230-9c9e07142700:image.png)
    
- **★ Variable Routing (변수 경로) ★**
    - URL 일부에 변수를 포함시키는 것 (변수는 view함수의 인자로 전달할 수 있음)
    - 동일한 주소에 **변수만 바뀌는 식**으로 적용
    - 작성법
        - path_converter
            
            <path_converter:variable_name>
            
            ⇒ <변수타입:변수명>
            

### App URL mapping

- 2번째 앱 pages가 생기면…
    - import가 많아지고
    - 같은 패턴의 함수도 많아진다.
        
        → URL을 각자 app에서 관리하자
        
- include 함수
    - 프로젝트 내부 앱들의 url을 참조할 수 있도록 매핑하는 함수
        
        ⇒ URL의 일치하는 부분까지 잘라내고, 남은 문자열 부분은 후속 처리를 위해 include된 URL로 전달
        

### URL 이름 지정

- url 구조 변경하면….
    - url을 사용하는 모든 위치를 찾아가 변경해야 함..
        
        ⇒ URL에 이름을 지어주면 이름만 기억하면 되지 않을까?
        
- Naming URL patterns
    - URL 이름 지정하는 것 (path 함수의 name 인자를 정의해서 사용
    - [url.p](http://url.pt)y ⇒ urlpattens ⇒ path함수에 name 인자에 이름 작성
    - a, from태그의 주소에 {%  url 이름 %}으로 작성

### DTL URL tag

- ‘url’ tag
    - {% url ‘url nae’ arg1 arg2 %}
    - 주어진 URL 패턴의 이름과 일치하는 절대 경로 주소를 반환
    - 띄어쓰기를 통해 arg1, arg2를 입력하면 자동으로 하위 주소로 작성된다.
