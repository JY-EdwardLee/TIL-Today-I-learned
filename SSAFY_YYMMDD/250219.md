# Queue

## 큐(Queue)?

- 스택과 마찬가지로 삽입과 삭제의 위치가 제한적인 자료구조
    - 큐의 뒤에서는 삽입만 하고, 큐의 앞에서는 삭제만 이루어지는 구조
- **선입선출구조** (FiFO, First In First Out)
    - 큐에 삽입한 순서대로 원소가 저장되어, 가장 먼저 삽입(First In)된 원소는 가장 먼저 삭제(First Out) 된다.
    - 머리와 꼬리, 두 개의 정보 필요
    - 기본 연산
        - 삽입 : enQ (push와 유사한 표현)
        - 삭제 : deQ (pop와 유사한 표)
    
    ※ 중간에서 꺼내는 것을 금지함
    
- 주요 연산
    - enQ(item) : 큐 뒤쪽에 원소를 삽입
    - deQ : 큐 앞쪽에서 원소 삭제
    - createQ : 공백 큐 생성
    - isEmpty : 큐가 공백인지
    - isFull : 큐가 포화상태인지
    - Qpeek : 앞쪽에서 원소를 삭제 없이 변환하는 연산

### 선형큐

- 1차원 배열을 이용한 큐 (기본)
    - 큐의 크기 = 배열의 크기
    - front : 저장된 첫 번째 원소의 인덱스
    - rear : 저장된 마지막 원소의 인덱스
- 상태 표현
    - 초기 상태 : front = rear = -1
    - 공백 상태 : front == rear
    - 포화 상태 : rear = n-1
- 삽입
    - 마지막 원소 뒤에 새로운 원소를 삽입하기 위해
        1. rear 값 하나 증가, 새로운 원소 삽입 자리 마련
        2. 그 인덱스에 해당하는 배열 원소 저장 (Q[rear])
- 삭제
    - 가장 앞에 있는 원소를 삭제하기 위해
        1. front 값을 하나 증가시켜 큐에 남아있는 첫 번째 원소 이동
        2. 새로운 첫 번째 원소를 리턴 함으로써 삭제와 동일한 기능
- 검증
    - isEmpty : front == rear
    - isFull : rear = n-1

※ append, pop은 동작이 느려 사용하지 않는 걸 권장

### 원형 큐

- 선형 큐의 잘못된 포화상태 인식
    - 배열의 앞 부분에 빈 공간이 있음에도 full로 인식해 이용하지 못하게 됨
- 해결방법 1
    - 연산이 이루어질 때마다 원소의 배열을 한 칸 앞으로 이동 ⇒ (비효율적)
- **해결방법 2 (원형 큐)**
    - 1차원 배열을 사용하되, 논리적으로 배열의 처음과 끝이 연결되어 원형형태의 큐를 이룬다고 가정하고 사용
- 원형 큐 구조
    - 초기 공백
        - front = rear = 0
    - 인덱스 순환
        - front 자리는 항상 비워 놓고 작업
    - front 변수
        - front가 있는 자리는 사용하지 않고 “항상 빈자리”로 둠
    - 삽입 삭제 위치
        
        
        |  | 삽입위치 | 삭제위치 |
        | --- | --- | --- |
        | 선형큐 | rear += 1 | front  += 1 |
        | 원형큐 | rear =(rear+1) mod n | front = (front+1) mod n |
        
        ※ mod = 나머지
        
        (i+1)%n → 자동으로 순환이 
        
    - 공백 및 포화 상태 검사
        - 선형 큐와 동일
            - front와 rear가 같으면 empty
        - 한자리 비어있기 때문에, 다음 자리 front가 배열 상으로 비어있더래도 full
            - (rear+1)%n == front 면 full
    
    ※ 사실 알고리즘을 풀 때는 선형 큐가 더 편할 때도 있다.
    

### 연결 큐

- 단순 연결 리스트(linked list)를 이용한 큐
    - 큐의 원소 : 단순 연결 리스트의 노드
        
        ※ 노드 : 데이터와 레퍼런스 주소를 저장할 2칸 짜리 리스트
        
    - 큐의 원소 순서 : 노드의 연결 순서. 링크로 연결되어 있음
    - front : 첫 번째를 가리키는 링크
    - rear : 마지막 노드를 가리키는 링크
- 굉장히 빠름
- 상태 표현
    - 초기 상태 : front = rear = null
    - 공백 상태 : front = rear = null
- 연산 과정
    - enQ :
        - 새로운 노드 생성 및 원소 삽입
        - A에 새로운 노드의 레퍼런스 주소 저장
        - rear에 새로운 노드 저장
- deque(덱)
    - 컨테이너 자료형 중 하나
    - deque 객체
        - 양쪽 끝에서 빠르게 추가와 삭제를 할 수 있는 리스트류 컨테이너
    - 연산
        - appedn(x) : 오른쪽에 x 추가
        - popleft(x) : 왼쪽에서 요소를 제거하고 반환, 요소가 없으면 indexError
        
        ```jsx
        from collections import deque
        
        q= deque()
        q.append(q)
        t = q.popleft()
        ```
        

### 우선순위 큐

- 특징
    - 우선순위를 가진 항목들을 저장하는 큐
        - FIFO 순서가 아니라 우선순위 대로 먼저 나가게 된다.

- 구현
    - 배열을 이용한 우선순위 큐
    - 리스트를 이용한 우선순위 큐
- 배열
    - 문법적으로는 배열이지만, 자료구조는 트리
    - 저장할 때 우선순위에 맞추어 적절한 위치에 삽입
    - 배열을 아용하므로, 삽입이나 삭제 연산이 일어날 때 원소의 재배치가 발생함

### 버퍼

- 데이터를 한 곳에서 다른 한 곳으로 전송하는 동안 일시적으로 그 데이터를 보관하는 메모리 영역
- 버퍼링 : 버퍼를 활용하는 방식 또는 버퍼를 채우는 동작
- 자료 구조
    - 버퍼는 일반적으로 입출력 및 네트워크와 관련된 기능에서 이용
    - 순서대로 입/출력/전달되어야 하므로 FIFO 방식의 자료구조인 큐가 활용됨
