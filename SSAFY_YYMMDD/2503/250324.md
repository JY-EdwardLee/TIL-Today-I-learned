### 가상환경

- 하나의 컴퓨터 내 **독립된** 파이썬 환경
    - 독립된 기능과 환경에서 프로젝트를 진행하기 위해
1. 가상환경 생성
    
    ```bash
    python - m venv **venv**(이름, 변경 가능- 사실 변경불가능..)
    ```
    
2. 가상 환경 활성화
    
    ```bash
    source venv/Scripts/activate
    ```
    
3. 가상환경 종료
    
    ```bash
    deactivae
    ```
    
- 가상환경 주의사항
    1. 가상환경은 On/Off 이다. (드나드는 것 X)
    2. 프로젝트마다 별도 가상환경
    3. venv는 관련 프로젝트와 동일한 경로에 위치
    4. 폴더 venv는 .gitignore세팅

### Django design pattern

- 디자인 패턴
    - 소프트웨어 설계에서 발생하는 문제를 해결하기 위한 일반적인 해결책
        
        (공통적인 문제를 해결하는 데 쓰이는 형식화 된 관행)
        
        → 어플리케이션 구조는 이렇게 구성하자~
        
- MVC 디자인 패턴
    - Model, View, Controller
    - 어플리케이션을 구조화하는 대표적인 패턴
    - 데이터 & 사용자 인터페이스 & 비즈니스 로직을 분리
        
        → 시작적 요소와 뒤에서 실행되는 로직을 서로 영향 없이, 독립적이고 쉽게 유지되도록 관리
        
- MTV 디자인 패턴 (ver. Django)
    - Model, Template, View
    - 이름만 다르고 모델의 구조는 똑같음
    
    ※ Python 특) Pythonic 하다~
    

### 프로젝트와 앱

- Django Project
    - 어플리케이션의 집합 (DB 설정, URL 연결, 전체 앱 설정 등…)
- Django application
    - 독립적으로 작동하는 기능 단위 모듈
- 앱 사용하기 위한 순서 **(약속)**
    
    ※ 순서를 지키지 않으면 안 만들어짐..
    
    1. 앱 생성
    2. 앱 등록
1. 앱 생성
    - 앱 이름은 복수형으로 표기
    
    ```bash
    python manage.py startapp **articles(앱 이름)**
    ```
    
2. 앱 등록
    - [settings.py](http://settings.py) > INSTALLED_APPS 배열 맨 앞에 등록
    - 항상 문자열로 작성하기 **(왜 why? 그냥 그렇게 하기로 했으니까)**

- 구조
    - 프로젝트 구조
        - 우리가 보는 곳
            - settings.py
            - urls.py
        - 나중에 볼 곳
            - 나머지 파일들
    - 앱 구조
        - 우리가 보는 곳
            - [admin.py](http://admin.py)
            - [models.py](http://models.py) ⇒ model 역할
            - [views.py](http://views.py) ⇒ view 역할
        - 나중에 볼 곳
            - 나머지
    - migrations ⇒ model 다룰 때 할 것

### 요청과 응답

- [urls.py](http://urls.py) 파일 관리하기
- **end slash, url 주소는 항상 ‘/’로 끝내라 (약속)**
- urldefs.py
    
    ```python
    urlpatterns = [
        path('admin/', admin.site.urls),
        # 약속 항상 /(end slash)로 끝내기
        path('articles/', views.index),
    ]
    ```
    
    - path(’articles/’, view.index)
    - articales로 요청이 오면, request 객체를 views 모델에 전달해라
- views.py
    
    ```python
    # 인자명 request는 약속 (바꿀 수 있는데, 바꿀 수 없음)
    def index(request):    # 메인 페이지 응답 (request) = 약속 객체 반환
        return render(request, 템플릿 경로 = articles/index.html) # templates는 약속이기 때문에 파라미터에서 생략
    ```
    
- templates 폴더 생성
    - app 디렉토리 내에
    - **templates 폴더 (약속, 이름 꼭 지키기 - 이름 다르면 그냥 망함**)
        - 하위에 template 파일 생성
