### READ

- 단일 게시글 조회하기
    - 단일 게시글을 보려면
        - URL을 변수화 시켜야한다.
            
            ⇒ url이 view함수에 적용되어야 한다.
            

### CREATE

- 2개의 함수가 필요함
    1. new
        - 사용자 입력 데이터를 받을 페이지를 렌더링
    2. create
        - 사용자가 입력한 요청 데이터를 받아 DB에 저장
- new
    - input
        - method = GET or POST
    - form
        - name ← 서버와 연결을 위해 필수적을 ㅗ입력

### HTTP request methods

- HTTP
    - 네트워크 상에서 데이터(리소스)를 주고 받기위한 약속
- ‘GET’ method
    - 서버로부터 데이터를 요청하고 받아오는 데**(조회)** 사용
        
        e.g. 검색
        
    1. 데이터 전송 : URL을 통해 데이터 전송 (쿼리 문자열)
    2. 데이터 제한 : URL 길이에 제한이 있어 대량의 데이터 전송에는 적합하지 않음
    3. 브라우저 히스토리
    4. 캐싱
        - 브라우저는 GET 요청의 응답을 로컬에 저장
        - 동일한 URL 요청 시, 서버에 접속하지 않고 저장된 결과 사용
        - 페이지 로딩 시간 단축
- ‘POST’ method
    - 서버에 데이터를 제출하여 리소스를 변경**(생성, 수정, 삭제)** 하는 데 사용
    1. 데이터 전송 : HTTP body를 통해 전송
        - 개발자 도구 > Network > Payload에서 확인 가능
    2. 데이터 제한 : GET에 비해 많은 데이터 전송
    3. 브라우저 히스토리 : POST 요청은 브라우저 히스토리에 남지 않음
    4. 캐싱
        - POST 요청은 캐시 불가능
        - POST 요청이 일반적으로 서버의 상태를 변경하는 작업을 수행하기 때

### POST

- HTTP response status code
    - 서버 클라이언트의 요청에 대한 처리 결과를 나타내는 3자리 숫자
- e.g.
    - 403 Forbidden
        - 서버에 요청이 전달되었지만, **권한** 때문에 거절되었다
        - CSRF token 누락
    - CSRF (Cross-Site-Request-Forgery)
        - 사이트 간 요청 위조
        - 사용자가 자신의 의지와 무관하게 공격자가 의도한 행동을 하여 특정 웹페이지를 보안에 취약하게 하거나 수정, 삭제 등의 작업을 하게 만드는 공격 방식
        - CSRF 토큰을 통해서 확인
    - why Token 확인?
        - 생성, 수정, 삭제 같은 기술적인 영역으로 DB조작이 가능하기 때문

### Redirect

- Create를 한 후에 페이지를 reponse하는 건 POST에 어울리지 않는다. (GET이면 모를까..)
- 데이터 저장 후 적절한 페이지로 사용자를 보내야한다.
    - but, 직접 다른 페이지로 보내는 건 안된다.
    
    ⇒ 실제로 서버가 클라이언트를 직접 다른 페이지로 보내는 것이 아닌 클라이언트가 GET요청을 한번 더 보내도록 응답하는 것
    
- redirect()
    - 클라이언트가 인자에 작성된 주소로 다시 요청을 보내도록 하는 함수
        1. POST 게시글 작성 요청(with 입력 데이터)
        2. create view 함수 호출
        3. redirect 응답 (detail 주소로 요청을 보내라)
        4. [GET] detail 페이지 요청
        5. detail view 함수 호출
        6. detail 페이지 응답

    2. update
