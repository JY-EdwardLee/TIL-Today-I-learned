# TREE

### 트리

- 비선형 구조 (원소들 간에 1:n 관계를 가지는 자료구조)
- 원소들 간에 계층관계를 가지는 계층형 자료구조
- 상위 원소에서 하위 원소로 내려가면서 확장되는 트리(나무)모양의 구조
- **정의 :** 한 개 이상의 노드로 이루어진 유한 집합
    - **최상위 노드**를 정해야함 ⇒ 루트(root) = 최상위 노드
    - 나머지 노드들은 n개의 분리 집합으로 분리 가능 ⇒ 서브 트리
    - T1 ~ TN(서브트리) 는 하나의 트리(재귀)가 됨
        - 가장 끝에 있는 노드 = leaf(잎) 노드
    - 간선 : 노들르 연결하는 선, 부모 노드와 자식 노드를 연결
        - 부모 노드, 자식 노드 = 상위 노드, 하위 노드
        - 형제 노드 : 같은 부모 노드의 자식 노드
        - 조상 노드 : 간선을 따라 루트 노까지 이르는 경로에 있는 모든 노드들
        - 자손 노드 : 서브 트리에 있는 하위 레벨의 노드
    - 차수
        - 노드의 차수 : 노드에 연결된 자식 노드의 수
        - 트리의 차수 : 트리에 있는 노드의 차수중에서 가장 큰 값
        - 리 노드 : 차수가 0인 노드
    - 높이
        - 노드의 높이 : 루트에서 노드에 이르는 간선의 수
        - 트리의 높이 : 트리에 있는 노드의 높이 중에서 가장 큰 값

## 이진 트리

- 모든 노드들이 2개의 서브트리를 갖는 특별한 형태의 트리
- 각 노드가 자식 노드를 최대 2개 까지만 가질 수 있는 트리
    - 0, 1, 2개
- 특성
    - 레벨 i에서의 노드의 최대 개수는 2^i개
    - 높이 h(0부터)인 이진 트리의 노드 개수는 (h+1) ≤ 노드 개수 ≤ 2^(h+1) - 1
- 종류
    - 포화 이진 트리(Full Binary Tree)
        - 모든 레벨에 노드가 포화상태로 차 있는 이진 트리
        - 노드의 개수 : 2^(h+1) - 1
        - 루트를 1번으로 하여 정해진 위치에 대한 노드 번호를 가짐
    - 완전 이진 트리 (Complete Binary Tree)
        - 높이가 h이고 노드 수가 n개일 때, 포화 이진 트리의 노드 번호 1번부터 n번까지 빈 자리가 없는 이진 트리
    - 편향 이진 트리 (skewed)
        - 높이 h에 대한 최소 개수로 이루어진 이진트리
- 순회 : 트리의 노드들을 체계적으로 방문하는 것
    - 선후 관계가 없는 트리는 순회를 위한 특별한 방법이 필요하다.
    - 3가지 방법
        - 전위순회 VLR
            - 부모 → 자식좌 → 자식우
        - 중위순회 LVR
            - 자식좌 → 부모 → 자식우
        - 후위순회 LRV
            - 자식좌 → 자식우 → 부모
- 전위 순회
    - 수행 방법
        1. 현재 노드 n을 방문처리
        2. 현재 노드 n의 왼쪽 서브트리 이동
        3. 현재 노드 n의 오른쪽 서브트리로 이동
    
    ```markup
    (pseudo)
    def preorder_traberse(T):
    	if T:
    		visit(T)
    		preorder_traverse(T.left)
    		preorder_traverse(T.right)
    ```
    
- 중위 순회
    - 수행 방법
        1. 현재 노드 n의 룅ㄴ족 서브트리 이동
        2. 현재 노드 n을 방문하여 처리
        3. 현재 노드 n의 오른쪽 서브트리 이동
    
    ```markup
    (pseudo)
    def preorder_traberse(T):
    	if T:
    	  preorder_traverse(T.left)
    		visit(T)
    		preorder_traverse(T.right)
    ```
    
- 후위 순회 (특 : 루트가 가장 마지막에 처리)
    - 수행 방법
        1. 현재 노드 n의 왼쪽 서브트리로 이동
        2. 현재 노드 n의 오른쪽 서브트리로 이동
        3. 현재 노드 n을 방문하여 처리
    
    ```markup
    (pseudo)
    def preorder_traberse(T):
    	if T:
    	  preorder_traverse(T.left)
    		preorder_traverse(T.right)
    		visit(T)
    ```
    

### 이진 트리의 표현

1. 포화/완전 이진 트리의 정점 번호를 따를 때
    - 배열을 이용한 이진 트리의 표현
        - 이진 트리에 각노드 번호를 부여
            - 루트 번호 1번
            - 레벨 n에 있는 노드에 대하여 왼쪽부터 오른쪽으로 2^n → 2^(n+1) - 1 까지
        - 포화, 완전 이진트리
    - 노드 번호의 성질
        - 노드 번호가 i인 노드의 부모 노드 번호 = i//2
        - 노드 번호가 i인 노드의 왼쪽 자식 노드번호 2*i
        - 노드 번호가 i인 노드의 오른쪽 자식 노드 번호 2*i + 1
        - 레벨 n의 노드 번호 시작 번호 2^n

### 이진 트리의 저장

1. 부모 번호를 인덱스로 자식 번호를 저장
    - 자식은 최대 2명이기에, 자식 array(1차원 배열)가 두개가 되줘야 함
    
    for i: 1 → N:
    
    read p, c
    
    if c1[i] == 0
    
    c1[i] = c
    
    else
    
    c2[i] = c
    
2. 자식 번호를 인덱스로 부모 번호 저장
    - 부모는 하나이기에, 부모 array(1차원 배열) 하나면 됨
    
    for i : 1 → N
    
    read p, c
    
    par[c] = p
    
    - 루트 찾기, 조상 찾기 할 때 사용
        
        e.g. 5번 노드의 조상 찾기
        
        c = 5
        
        while (a[c] ≠ 0)
        
        c = a[c]
        
        anc.append(c)
        
        root = c
        
- 배열을 이용한 이진트리의 단점
    - 메모리 공간 낭비
    - 노드 삭제시 배열 크기 변경 어려움
- **연결 리스트**
    - 하나의 배열에
        - 왼쪽 자식 노드 주소 | 데이터 | 오른쪽 자식 노드 주소
- **수식 트리**
    - 수식을 표현하는 이진 트리
        - 피연산자 = 리프노드
        - 연산자 = 루트 or 가지 노드

### 이진 탐색 트리

- why 탐색?
    - 대량의 데이터를 잘 관리하고 싶은데
        - 배열 : 데이터 삽입/삭제 비효율적 (O(n))
        - 연결 리스트 : 검색이 비효율적 (O(n))
        - 데이터 양이 많아질 수록 성능 저하
- 탐색작업을 효율적으로 하기 위한 자료구조
- 모든 원소는 서로 다른 유일한 키
- 왼쪽 서브트리 < 루트노드 < 오른쪽 서브트리
- 탐색 연산
    - 루트에서 시작한다
    - 탐색할 키 값 x를 루트 노드의 키값과 비교한다.
        - 같으면 : 원하는 원소 찾았으므로 탐색 끝
        - 키가 더 작으면 : 왼쪽 탐색연산
        - 키가 더 크면 : 오른쪽 탐색연산
- 삽입 연산
    1. 먼저 탐색 연산을 수행
    2. 탐색 실패한 위치에 원소 삽입
- 삭제 연산
    - 삭제 연산 케이스
        - 삭제할 게 **리프노드** 일 때
            
            → 탐색, 삽입과 같음
            
        - 삭제할 **노드가 하나의 자식**을 가지고 있을 때
            
            → 삭제할 노드의 부모 노드에 물려주고 죽으면 됨
            
        - 삭제할 **노드가 두개의 자식**을 가지고 있을 때
            
            → 중위 후속자 vs 중위 전임자
            
            - **중위 후속자** : 삭제할 노드의 오른쪽 서브트리에서 갖아 작은 값
            - 중위 전임자 : 삭제할 노드의 왼쪽 서브트리에서 가장 큰 값
            - BST 구조를 유지하기 위해서 삭제할 노드와 가장 가까운 값을 찾는 것
            
            중위 후속자는 항상 **‘하나의 자식’ 또는 ‘리프노드**’이기 때문에 재귀적으로
            
            위의 두가지 경우를 다시 실행하여 지우면된다.
            
    1. 먼저 탐색 연산을 수행
    2. if 자식이 두 개 있는 노드:
        - 왼쪽 서브트리 중 가장 오른쪽에 있는 녀석을 삭제한 위치에 삽입
- 시간 복잡도
    - 탐색, 삽입, 삭제 : O(h) h: 트리의 높이
- 평균의 경우
    - 이진 트리가 균형적으로 생성되어 있는 경우
    - O(log n)
    
    ※ red-black tree, AVL
    
- 최악의 경우
    - 한쪽으로 치우친 경사 이진트리의 경우
    - O(n)
    - 순차탐색과 시간복잡도가 같다.

### 힙(heap)

- **완전 이진 트리**에 있는 노드 중에서 키값이 가장 큰 노드나 키값이 가장 작은 노드를 찾기 위해서 만든 자료구조
- 제일 위에 있는 루트 값(최대, 최소)만 쓰려고 함
    - 최대 힙 (max heap)
        - 키값이 가장 큰 노드를 찾기 위한 **완전 이진 트리**
        - 부모노트 > 자식노드
        - 루트 노드 : 키 값이 가장 큰 노드
    - 최소 힙 (min heap)
        - 키값이 가장 작은 노드를 찾기 위한 **완전 이진 트리**
        - 부모노트 < 자식노드
        - 루트 노드 : 키 값이 가장 작은 노드

★ **삽입, 삭제, 정렬 등의 과정을 할 때 항상 완전 이진 트리 구조를 유지해야 함**

- **삽입 (logN)**
    - 리프 노드에 추가
        - 조건
            1. 완전이진트리
            2. 부모 > 자식
        - 방식
            1. Last 찾기
            2. Last+1 새로 갱신. 삽입
    - 부모 자식 비교하기
        1. 부모 자식 확인
        2. 자리 바꾸기
        3. 부모 > 자식 or 부모가 없을 때 까지 1~2 반복
- **삭제 (logN)**
    - 조건
        - 완전이진트리 유지
        - 부모 > 자식
    1. 루트 원소 삭제 및 보관
    2. 마지막 노드 삭제 및 루트에 복사
    3. 자리 바꾸기
- **정렬**
    
    ※ heapq 모듈 : 리스트를 최소 힙으로 바꿔 줌
    
    heapq.heapify(x)
    
    heappush(x, 1)
    
    heapppop(numbers)
    
    최대 힙으로 바꾸고 싶으면 마이너스로 바꿔주면 된다.
    

### 우선순위 큐

- 우선순위 가진 항목들을 저장하는 큐
- 최대, 최소 위치에 있는 값에 우선순위를 줘서 먼저 팝하는 방식
    - 하지만, 하위에 있는 노드들은 정렬이 안되어 있기 때문에 순서 보장 X
