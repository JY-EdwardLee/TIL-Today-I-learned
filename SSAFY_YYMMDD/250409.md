# N : 1

## N:1 or 1:N

: 한 테이블의 0개 이상의 레코드가 다른 테이블의 레코드 한 개와 관련된 관계

※ **0개 이상(없을 수도 있음) →** **1개**

e.g. Comment - Article (1개의 게시글에 n개의 댓글(무플도 가능))

⇒ Comment(N)에 FK 필드가 필요

### ForeignKey()

- 한 모델이 다른 모델을 참조하는 관계를 설정하는 필드
    
    ⇒ N:1  관계 표현
    
    ⇒  데이터베이스에서 외래 키로 구현
    
- 댓글 모델 정의 (작성법)
    - ForeignKey의 속성명은 모델 클래스 이름의 **단수형** 권장 (장고에서 권장 = 필수)
    - 작성 위치는 무관 (어디에 하던 항상 마지막 필드로 생성됨)
- ForeignKey의 인자
    - to ⇒ 참조하는 모델 class
    - on_delete ⇒ 참조된 객체가 사라졌을 때 어떻게 처리할 것인가?
        - CASCADE = 참조하는 모든 객체도 삭제 됨
        - PROTECT, RESTRICT 등…
        - https://docs.djangoproject.com/en/5.1/ref/models/fields/#:~:text=db.models%3A-,CASCADE%5Bsource%5D%C2%B6,-Cascade%20deletes.%20Django
    - 테이블에 만들어지는 필드 이름
        - 외래키 필드 : ‘참조 대상 클래스(클래스 인스턴스명) _ id’

### 댓글 생성하기

1. Comment 클래스 인스턴스 생성
2. 인스턴스 변수 저장
3. 외래키를 지정할 article 인스턴스 생성
4. comment.article = article
5. comment.save()

※ 객체 지향적으로 하기 위해서는, article_id 필드에 직접 부여하기 보다는 인스턴스를 생성하는 게 바람직하다.

※ DB의 comment.article_id 에는 article의 pk값이 들어가지만, comment와 article 객체의 논리적 연결이 되어서 comment.article로 바로 article 게시글 참조가 가

### 관계 모델 참조

- 역참조 (1 → N 방향으로 참조하기)
    - Django에서 도와줌 ⇒ 역참조 키워드 제공
    
    ※ 참조 : 1번 댓글이 작성된 게시글 정보, 역참조 : 1번 게시글에 달린 모든 댓글 정보
    
    ```python
    article.**comment_set**.all()
    # instance.related manager.QuerySet API
    => 특정 게시글에 작성된 갯글 전체를 조회하는 요
    ```
    
- related manager
    - 역참조 시 이용하는 매니저
    - ‘모델명_set’ 형식

### 댓글 CREATE 구현

1. CommentForm 정의 (article 필드는 제외)
2. comment의 모델폼 만들기
3. detail view 함수에 comment form 추가
    - detail.html파일에 렌더링
4. url 작성 및 action 값 추가
5. comments_create 함수 정의
    
    **★ save(commit=False)를 통해 DB 저장 없이 인스턴스만 생성**
    
    ⇒ FK 참조
    
    ⇒ 다시 .save()로 저장
    

### 댓글 DELETE 구현

1. urls 작성 (url 규칙을 지켜서 article_pk, comment_pk 둘 다 받기)
2. view 함수 정의
3. detail.html에 삭제 버튼 렌더링

※ No reverse Match ⇒ 무조건 url 에러
