# N:M

## Many to many relationships 01 (N:M or M:N)

: 한 테이블의 0개 이상의 레코드가 다른 테이블의 0개 이상의 레코드와 관련된 경우

※ 양쪽 모두에서 N:1 관계를 가짐

- M:N 관계의 필요성
    - N:1의 한계

### N:1의 한계

- N:1관계에서는 외래키의 관점에서 봤을 때, 동일한 DB가 또 생기기도 함
    - 다른 PK의 동일한 사람 (DB 상으로는 다른 사람이나 마찬가지)
- 외래키 컬럼에서 두개의 인자를 넣는 것도 불가능

⇒ 예약 모델을 따로 만들어야 함 (중개모델)

### ☆ 중개모델

- 환자의 외래키 삭제
- 예약 모델 (중개모델)
    - 의사와 환자에 각각 N:1관계를 가지는 모델
- reservation 모델을 역참조하여 자신의 예약 관계 파악 가능

⇒ Django에는 **중개모델** 자동 생성 Field 존재

### ManyToManyField() (중개모델 자동 생성 Field)

- 특징
    - 양방향 관계
    - 중복 방지
- ManyToManyField(참조대상)
- 새로 나온 API
    - add
        - patient1(인스턴스).doctors(참조대상).add(doctor1(객체))
        - 참조 역참조 관계로 각 인스턴스 측에서 추가 가능
    - remove
        - doctor1(인스턴스).patient_set(역참조대상).remove(patient1(객체))
- class
    - to : 누구랑 관계를 할 것인지
    - related_name
        - 역참조 manager name 수정 (default = patient_set)
        
        ※ 1:1 관계에서는 권장하지 않고, N:N관계에서 활용될 가능성 높음
        
        +) 한번 수정하면 _set 못 씀
        
        - 다대다 관계에서는 반드시 복수형 권장 (django에서 권장은 필수)
    - symmetrical
        - 재귀적인 관계에서만 사용 (방향성 존재)
            - 본인 스스로와 관계를 맺을 때
            - 중계 테이블에 ‘self’로 생성
            - symmetrical = True
                - 방향성이 존재하기 때문에, 두개의 id가 다른 column일 시 중복 생성 가능
                - 자동으로 대칭 생성
            - (default) symmetrical = False
    - ‘through’ argument
        - 중계 테이블에 추가 정보가 있는 경우 활용
            - add
                - through_defaults에 {’column’: value} 데이터를 입력해서 add
    

### 좋아요 기능 구현

- Article(M) - User(N)
    
    : 0개 이상의 게시글은 0명 이상의 회원과 관련
    
    ⇒ 게시글은 회원으로부터 0개 이상의 좋아요를 받을 수 있고, 회원은 0개 이상의 게시글에 좋아요를 누를 수 있음
    

```python
"""M:N 관계 설정 시 그냥 복수형으로 이름을 짓는 것 보다,
    지금 우리가 만드는 기능이 무엇인지 생각해보고 명시적인 Manager이름을 설정하는 것이 좋다.

    게시글1.users.all() => 게시글1.like_users.all()

    Article과 User는 N:1관계 N:M 관계 두번의 관계가 맺어져 있다.
    이 때에 article 쪽에 user를 manytomany 관계를 맺게 되면
    user.article_set 매니저명이 겹치는 문제가 발생"""
  
  like_users = models.ManyToManyField(settings.AUTH_USER_MODEL, related_name='like_articles')
```

### select_related & prefetch_related

- select_related(외래키로 조인할 필드) ⇒ 1:N에서 씀
    - INNER JOIN 활용
    - 인자로 넣은 테이블을 조인하여 건냄
- prefetch_related(필요한 필드) ⇒ 좀 더 복잡할 때
    - 두개의 쿼리로 각 테이블을 가져온 
    Python을 사용한 JOIN 활용
    - 인자로 넣은 테이블을 전부 가져옴
