# SQL

### 데이터베이스란?

: 체계적인 데이터 모음

- 데이터
    - **저장**이나 **처리**에 효율적인 형태로 변환된 정보
- 데이터 저장 방법
    1. 파일을 이용한 데이터 관리 (.txt)
        - 어디서나, 쉽게 이용 가능
        - 데이터를 구조적으로 관리하기 어려움
    2. 스프레드 시트를 이용한 데이터 관리
        - 테이블의 열과 행을 사용해 데이터를 구조적으로 관리 가능
        - 한계
            - 크기 : 100만 행이 최대.
            - 보안 : 링크 소유 여부에 따른 단순한 접근 권한 기능 제공
            - 정확성
                - 시트의 내용 변경 시 누락이 생기는 등 완벽하게 정확성을 보장할 수 없음
    
    ⇒ 데이터베이스의 역할
    
    데이터를 저장하고 조작(CRUD)
    

### Relational Database

- 관계형 데이터베이스
    
    : 데이터 간에 **관계**가 있는 데이터 항목들의 모음
    
    - 테이블, 행, 열의 정보를 구조화하는 방식
    - **서로 관련된 데이터 포인터를 저장**하고 이에 대한 **액세스**를 제공

### 관계

: 여러 테이블 간의 (논리적) 연결, 여전히 테이블들은 독립적이다.

- 관계로 할 수 있는 것
    - 이 관계로 인해 두 테이블을 사용하여 데이터를 다양한 형식으로 조회할 수 있음
- 관계형 DB 예시
    - 각 데이터를 비교하기 위한 값: PK(Primary Key)
    - 다른 테이블을 참조하는 고유한 식별 값 : FK(Foreign Key)
- RDB 키워드
    - Table( a.k.a Relation) : 데이터를 기록하는 곳
    - Field ( a.k.a Column, Attribute) : 고유한 데이터 형식이 지정
    - Record (a.k.a Row, Tuple) : 각 레코드에는 구체적인 데이터 값 저장
    - Database (a.k.a Schema) : 테이블의 집합
    - Primary Key : 각 레코드(row)의 고유값, 관계형 데이터베이스에서 **레코드 식별자**로 활용
    - Foreign Key : 관계형 데이터베이스에서 레코드의 식별자로 활용이콘 추가

### RDBMS

- DBMS : 데이터베이스 관리 소프트웨어 프로그램
- RDMBS : 관계형 디비를 관리하는 소프트웨어 프로그램

- SQLite
    - 경량의 오픈 소스 데이터베이스 관리 시스템
        
        ⇒ 컴퓨터 모바일 기기에 내장되어 간단하고 효율적인 데이터 저장 및 관리 제공
        

### SQL (Struecure Query Language)

(테이블 형태로 **구조화**된 관계형 데이터베이스에게 요청을 **질의-요청**)

- 데이터베이스에 정보를 저장하고 처리하기 위한 프로그래밍 언어

- SQL Syntax
    1. 대소문자 구분하지 않음
    2. 각 SQL Statements 끝에는 세미콜론 필요

- SQL Statements
    - SELECT, FROM 2개의 Keyword로 구성 됨
    - DDL, DQL, DML, DCL (CRUD)에 따라 달라짐
    
    | 유형 | 역할 | SQL 키워드 |
    | --- | --- | --- |
    | **DDL** (Data Definition Language) | 데이터의 기본 구조 및 형식 변경 | CREATE, DROP, ALTER |
    | **DQL (Data Query Language)** | **데이터 검색** | **SELECT** |
    | **DML** (Data Manipulation Language) | 데이터 조작 (추가, 수정, 삭제) | INSERT, UPDATE, DELETE |
    | **DCL** (Data Control Language) | 데이터 및 작업에 대한 사용자 권한 제어 | COMMIT, ROLLBACK, GRANT, REVOKE |

### SELECT

- SELECT statement
    
    : 테이블에서 데이터를 조회
    
    - SELECT syntax
        - SELECT
        (데이터를 선택하려는 필드를 하나 이상 지정) **(연산자)** **AS** ‘Column 명(조회하고 싶은)’
        FROM
        (데이터를 선택하려는 테이블의 이름을 지정) ;
    - ORDER BY
        - ORDER BY statement
            - 조회 결과의 레코드를 정렬
            - FROM 뒤에 위치
            - 하나 이상의 컬럼을 기준으로 결과를 오름차순(기본값), 내림차순(DESC)으로 정렬
                - 두 개의 컬럼을 기준 삼을 시 comma로 구분 (먼저 작성한 것이 우선)
            - SELECT . FROM . ORDER BY (DESC)
                - NULL은 오름차순 기준 항상 가장 빠
    - Filtering data
        - clause, operator
        - DISTINCT statement : 조회 결과에서 중복된 레코드를 제거
            - SELECT 키워드 바로 뒤에 (SELECT DISTINCT)
        - WHERE statement : 조회 시 특정 검색 조건을 지정
            - FROM clause 뒤에 위치 (FROM clause WHERE)
            - 비교연산자 및 논리연산자 사용
            - 다중 조건 : AND, OR 연산자 사용
            - NULL은 =(euqal) 연산자로 확인 불가능
                - 데이터베이스에서 NULL은 존재하지 않는디는 의미
                
                ⇒ NULL은 IS연산자 사용 (Company is NULL)
                
            - ORDER BY와 같이 쓸 때는, ORDER BY가 나중에 오도록
            - LIKE
                - %, _와 함께 쓰이는 연산자 (Wildcard Character)
                - & : 0개 이상의 문자열과 일치하는지
                - _ : 단일 문자와 일치하는지
        - LIMIT clause
            
            : 조회하는 레코드 수를 제한
            
            - offset 조회 시작 순서 row_count는 조회하는 최대 레코드수를 지정

### Grouping data

- GROUP BY
    
    : 레코드를 그룹화하여 요약본 생성 (’집계 함수’와 함께 사용)
    
    - 집계 합수 (Agg Func)
        - 값에 대한 계산을 수행하고, 단일한 값을 반환하는 함수
    - GROUP BY syntax
        - FROM 및 WHERE 절 뒤 (FROM WHERE GROUP BY)
    - WHERE은 집계 항목에 대한 세부조건을 지정할 수 없다
    - 원한다면 WHERE 대신 HAVING을 써라
